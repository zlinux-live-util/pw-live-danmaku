# 性能

本文汇总实测数据、开销的构成，以及继续压低开销该动哪个参数。测量条件除注明外均为默认
`480x1080` @30fps、消费者接满、`--font-size 28`。

## 指标

| 指标 | 数值 |
| --- | --- |
| CPU | **约 3.0% 单核** |
| 单帧耗时 | 约 1.0 ms |
| 无消费者连接时 | 渲染回调一次不被调用，面板侧开销为零 |
| 私有（匿名）内存 | **94 MB** |
| 子进程 | **0** |

原始测量窗口：

```text
window        : 30.0 s
frames pushed : 900  -> 30.0 fps
cpu           : 0.900 s  -> 3.00% of one core
per frame     : 1.000 ms
private memory: 94 MB
```

私有内存之外的部分是 cairo / pango / gdk-pixbuf / glib / curl / OpenSSL / PipeWire 等共享库与
fontconfig 缓存，属于系统级共享页，不会与其它进程重复占用。

## 开销的构成

三块，量级完全不同：

| 组成 | 随什么变 | 说明 |
| --- | --- | --- |
| 静态层整块拷贝 | **画布面积 × 帧率** | `480x1080x4` ≈ 2.1 MB/帧，帧率协商后按协商值走 |
| 每帧重画的头像圆盘 | **可见行数 × 帧率** | 框高等于一行行高，实测 36 个；半径跟着 `--font-size` 走 |
| 每条新消息 | **消息自身的行高 × 消息速率** | 上移一行 + 在新露出的条带里画这一条 |

**做法是静态层 + 增量移位。** 文字排好之后就不再变，所以整个画面累积在一张 ARGB32 静态层表面上；每来一条新消息，只把已有内容整体上移一行的高度，再在新露出的底部条带里画这一条。

- 「上移一行」是把表面画到自身偏移一行的位置——这是**自重叠 blit**，pixman 会正确处理重叠区，行为等同 `memmove`，不会糊。
- 因此**每条消息的开销正比于它自己的高度，而不是整个面板**。M0 的做法（每帧重新排版全部可见行）会让开销正比于可见行数 × 消息速率，在热闹房间里成为主要开销。
- 帧路径上没有新消息时，一帧就是一次整块拷贝。
- 滚出面板的行会被裁掉，因此不会随运行时长增长；面板也不保留已绘制的消息正文（像素已经在静态层里），所以帧回调不需要为它们分配任何东西。

**没有消费者连接时，流停在 `PAUSED`，渲染回调一次都不被调用**——所以 OBS 里没开这个源时，面板侧开销为零，留在面板上的只有站点线程的解析与下载。

## 协议侧解析开销

对 M2 那 242 份抓包做基准（`Json::parse` + `parseMessage` 全流程，含 base64 与 protobuf）：

```text
4.8 us per document
16 us per second of stream      （按 242 份 / 70 秒的实测速率折算）
```

即每秒输入占用约 **0.0016% 单核**，与渲染相比可以忽略。这份数字**不包含渲染**：测它的机器上没有
`pipewiresrc`，`make verify` 的落盘验证跑不了，所以渲染侧仍沿用上表那一份，没有重测。

## 继续压低开销

只有上面 3.0% 是实测值；下面按构成给出各参数**移动的是哪一块开销**，未单独重测：

- `--fps N`：直接乘在整块拷贝与头像圆盘上。`--fps 24` 大约省五分之一。
- `--size WxH`：只影响整块拷贝与折行宽度，`480x1080` 降到 `360x810` 约省掉三成拷贝量；行高不变，所以每条消息的开销不变。
- `--font-size` / `--card-font-size`：行高跟着走，于是同时压低「每条新消息」与「头像圆盘」两块。字号变小也意味着同样高度里能放更多行，观看效果上更密。
- `--entry-merge` / `--gift-merge` 调大：进入面板的行变少，直接减少「每条新消息」那一项。热门房间里入场是弹幕的 4 倍多，这是最有效的一个旋钮。
- `--gift-merge 0` / `--entry-merge 0` 会**反向**增加开销：每一份礼物、每一次入场都各占一行。

## 怎么测才准

- **精确窗口 + 帧数差值**，不要用日志里的推帧计数（取样会滞后）。
- 「0 tick」这个量级下测量方法本身是粗的（100 tick = 1s）。早期版本在 `480x900` 下曾量到「0 tick」，那是**采样错误**（读到了错误的进程或时刻）。只能说「远低于 3% 单核」，要更细的数需要 `perf` 或更长的采样。
- **必须挂上消费者**再测：没有消费者时渲染回调不执行，量到的只是解析与心跳。
- 端到端落盘验证（需要 `gst-launch-1.0` 与 `pipewiresrc`）：

  ```bash
  ./pw-live-danmaku --room 7734200 --seconds 45 &
  sleep 6
  gst-launch-1.0 -q pipewiresrc target-object=pw-live-danmaku num-buffers=10 ! \
      video/x-raw,format=BGRA ! filesink location=/tmp/frames.raw
  ls -l /tmp/frames.raw        # 实测 17280000 = 10 × 480 × 900 × 4，逐字节吻合
  ```
